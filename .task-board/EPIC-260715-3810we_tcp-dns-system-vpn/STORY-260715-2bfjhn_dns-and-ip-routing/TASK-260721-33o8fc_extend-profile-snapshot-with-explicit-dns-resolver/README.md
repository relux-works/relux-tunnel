# Extend the M1 profile snapshot with the explicit DNS resolver schema

## Description
Implement the versioned non-secret schema extension selected by TASK-260715-1tnjlu so profile loading, runtime configuration, DNS transport, migration, and fixtures share one canonical ordered resolver identity.

## Scope
In scope: dnsResolver schemaVersion 1 and kind dns53; a non-empty ordered list of numeric IPv4 or IPv6 endpoints bounded by the accepted DNSRuntimePolicyV1 from TASK-260721-3miqh4; port default 53; canonical normalization and rejection rules; RuntimeConfigurationSnapshot schema 2; bounded deterministic codecs; profile revision and configuration generation identity; requiresResolverConfiguration migration result; cache identity input; privacy-safe diagnostics; unit and golden fixtures. Out of scope: profile UI, DNS listener, upstream TCP or relay implementation, resolver discovery, public vendor defaults, DoH, physical resolver access, remote shell parsing, cache implementation, selecting unevidenced endpoint limits, and final copy.

## Acceptance Criteria
1. RuntimeConfigurationSnapshot schema 2 and its persistent profile input carry exactly dnsResolver.schemaVersion=1, kind=dns53, and a required non-empty ordered endpoint array whose address is a canonical numeric IPv4 or IPv6 literal and whose optional port defaults to 53; the active accepted DNSRuntimePolicyV1 supplies and validates the production endpoint-count ceiling. 2. Editor normalization canonicalizes valid textual IP input while the stored-snapshot validator requires canonical form; validation permits deliberate loopback, private, global, and IPv6 ULA endpoints, derives family from bytes, deduplicates tuples, and rejects empty or policy-oversized arrays, hostnames, brackets or zones, unspecified, multicast, limited-broadcast, link-local, mapped, non-canonical persisted, duplicate, zero, and out-of-range values before credentials or routes. 3. Schema-1 or persisted profiles missing dnsResolver remain preserved but return requiresResolverConfiguration and cannot reach Keychain, SSH, settings, or packet reads; unknown resolver versions or kinds fail closed and no migration copies a physical or product-default resolver. 4. Resolver kind, order, normalized address, and port participate in profile revision, runtime generation, channel identity, and cache-generation invalidation without entering default logs, diagnostics, providerConfiguration, or secret storage. 5. Deterministic codec, validation, compatibility, size-bound, IPv4, IPv6, loopback, ordering, duplicate, unknown-version, migration, privacy, and endpoint-count boundary fixtures use injected policy vectors from TASK-260721-3miqh4 and publish task-scoped schema vectors and commands.
