# Bind accepted M0 revisions for M1 production composition

## Description
Produce one immutable task-scoped binding manifest that releases M1 production dependency composition only after TASK-260715-nphtib, TASK-260715-2jatnd, and TASK-260715-1gjxer each have a reviewer-accepted outcome. Copy no implementation and perform no new selection. Identify the exact accepted outcome resource name and SHA-256, accepted source or binary pin, required capabilities, binding configuration values and ranges, license or maintenance obligations, revalidation triggers, and supersession status. Compare every binding against the approved M1 runtime contract and fail closed on absent, negative, ambiguous, stale, or mutually incompatible evidence.

## Scope
In scope: accepted-resource identity and digest; reviewer verdict identity; generated target and dependency graph constraints; PacketFlowBridge, HEV/lwIP, MTU, buffer, batching, session, notice, and fork disposition bindings; selected SSH adapter, dependency pin, algorithm, window, rekey, lifecycle, notice, and maintenance bindings; compatibility check against the runtime contract; machine-readable and human-readable manifest; explicit productionCompositionPermitted result. Out of scope: re-running M0 matrices, selecting or tuning packet or SSH implementations, changing M0 decisions, coordinator implementation, TCP or DNS behavior, routes, UI, UDP, lanes, reconnect, and human ratification.

## Acceptance Criteria
1. The outcome names TASK-260715-nphtib, TASK-260715-2jatnd, and TASK-260715-1gjxer plus each exact reviewer-accepted outcome resource, reviewer verdict, content SHA-256, and acceptance timestamp; no unaccepted note, source file, or inferred value is authoritative. 2. Every binding condition required by those outcomes is normalized into a manifest covering project graph, dependency direction, packet and HEV pins and values, selected SSH adapter and pin, mandatory capabilities, licenses, maintenance, and revalidation triggers. 3. The manifest sets productionCompositionPermitted=true only when all three inputs are accepted, current, internally compatible, and compatible with TASK-260715-30zng6; otherwise it records stable failing rows and leaves production composition blocked. 4. Deterministic validation recomputes resource digests, rejects missing or superseded evidence and unknown required fields or schema versions, and proves a changed upstream resource cannot silently retain permission. 5. TASK-260715-3ejhyy consumes this manifest as its sole M0 binding source and does not duplicate or reinterpret any M0 decision.
