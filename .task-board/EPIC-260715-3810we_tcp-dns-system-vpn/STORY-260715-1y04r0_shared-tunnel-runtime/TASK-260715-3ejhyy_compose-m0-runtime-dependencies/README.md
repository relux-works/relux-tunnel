# Compose M0-bound runtime sessions behind production factories

## Description
Implement the macOS production dependency factory and deterministic SPM harness factory consumed by ReluxTunnelCore using only the accepted M0 binding manifest from TASK-260720-1qhxqa. Construct the selected libssh2 bootstrap/transport, TCP and DNS consumers, M1PacketPlaneSession over the accepted PacketBridge API, macOS PacketFlow boundary, network-settings plan/application seams, clocks, metrics, logging, cancellation, memory pressure, immutable profile snapshot, mandatory host policy, system-domain Keychain credential resolver, and privacy-safe bootstrap diagnostics. M1PacketPlaneSession.prepare remains pure preflight; activateReads starts the accepted bridge only after settings are applied. iOS composition is deferred and excluded.

## Scope
In scope: binding-manifest schema and digest validation; productionCompositionPermitted enforcement; macOS and deterministic harness factories; one object graph per runtime generation; pure packet-plane preflight; post-settings activation through PacketBridge.start; private-ingress dispatch to TCP CONNECT and virtual-DNS UDP/TCP with other UDP rejected in M1; selected libssh2 wiring behind candidate-neutral boundaries; immutable profile, host-policy, system-Keychain and diagnostic dependencies; health and idempotent stop; ownership transfer and reverse release; accepted pins and configuration inputs; compile-time boundary guards; fail-fast behavior before routes for absent, superseded or incompatible bindings. Out of scope: iOS, changing PacketFlowBridge startup semantics, generating or reinterpreting M0 decisions, tuning engine/MTU/buffers/windows, coordinator transitions, TCP/DNS internals, route policy values, UI, general UDP, lanes and reconnect.

## Acceptance Criteria
1. The macOS production root and deterministic SPM harness root satisfy the same candidate-neutral session interfaces, while only production requires a valid accepted binding manifest. 2. Each generation creates packet, HEV, libssh2 SSH, TCP and DNS objects at most once; prepare acquires no descriptor, HEV lease/thread, private listener or PacketFlow read; activateReads separately starts the accepted bridge after settings; stop releases every acquired object in contract order. 3. Production fails before routes when composition is not permitted, any accepted resource digest or pin differs, a binding is superseded, or a mandatory capability is absent; no local default or task note substitutes. 4. No libssh2 concrete type, HEV C API, NEPacketTunnelProvider implementation, host-app object or live platform callback crosses an unintended shared boundary. 5. macOS and harness compile/smoke tests prove exact bound component resolution, pure preflight, post-settings start, DNS-only UDP dispatch, deterministic substitution, repeated cleanup and boundary-guard rejection of type leakage.
