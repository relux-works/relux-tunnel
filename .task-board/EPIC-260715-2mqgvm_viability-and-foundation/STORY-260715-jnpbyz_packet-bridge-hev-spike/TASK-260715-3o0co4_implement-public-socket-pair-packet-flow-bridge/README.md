# Implement the public socket-pair PacketFlowBridge

## Description
Implement the shared Swift PacketFlowBridge and descriptor-borrow seam exactly as specified by TASK-260715-p89bdj, including supervised run termination, public AF_UNIX/SOCK_DGRAM setup, framing, bounded pumps, metrics, privacy-safe failure, and exactly-once cleanup.

## Scope
In scope: bridge lifecycle actor and RunHandle; socketpair creation; FD_CLOEXEC and O_NONBLOCK on both endpoints; SO_SNDBUF/SO_RCVBUF request plus four effective readbacks; endpoint-B scoped borrow handle; forward and reverse four-byte network-order family framing; checked 4+MTU datagram ceiling; count/time work slices; normalized would-block and ENOBUFS bounded loss; fatal EMSGSIZE/peer EOF/persistent errors; run-scoped metric schema; privacy-safe logs; injected socket, readiness, descriptor-consumer, clock, logger, metrics, and lifecycle barriers. Out of scope: real HEV startup internals, SSH, routes, DNS, private APIs, final tuning constants, product UI, retry queues, and side buffers.

## Acceptance Criteria
1. Start/stop/failure tests prove endpoint A remains bridge-owned, endpoint B is only borrowed, no task is detached, and normal stop, cancellation, startup failure, and runtime failure join all children and the HEV borrow before closing B then A exactly once. 2. Forward sends exactly one [network-order AF word][unchanged IP packet] datagram per valid typed packet; reverse maps exactly one valid datagram to one ordered typed packet, while empty/undersized/unknown/mismatched frames follow the contract counters and zero-length datagrams are not treated as EOF. 3. Both endpoints preserve existing flags while gaining CLOEXEC/NONBLOCK, request both socket buffers, expose all requested/effective byte gauges, and enforce checked count/time work slices and the 4+MTU datagram ceiling without an application queue. 4. Darwin EAGAIN/EWOULDBLOCK normalize to the canonical would-block counters, ENOBUFS drops without retry, and EMSGSIZE, peer EOF, PacketFlow rejection, and unclassified persistent errors perform the single fatal transition with exact counters and one privacy-safe log. 5. Static inspection and injected-seam tests prove exact metric names/units/monotonicity/maxima, first-error-wins termination, no utun control access, no FD scanning/reopening/duplication, no unbounded retry or side buffer, and no sensitive log fields.
