# Implement exit-side DNS-over-TCP through SSH direct-tcpip

## Description
Implement the M1 DNS upstream transport that opens bounded SSH direct-tcpip channels to the resolver selected by the approved policy, writes and reads RFC-compatible TCP length-prefixed DNS messages, validates correlation and size, and returns explicit failure without any physical resolver fallback.

## Scope
In scope: normalized ordered resolver endpoints and port; one generation-scoped active endpoint and at most one reusable direct-tcpip connection; connection-epoch and upstream-ID correlation ownership; bounded ordered pipelining and out-of-order responses; injected DNSRuntimePolicyV1 message, byte, capacity, and timing limits; TCP length framing and partial I/O; per-query cancellation and deadline; connection-fatal EOF, framing, correlation, timeout, channel, and SSH failures; atomic in-flight classification; one coordinated endpoint promotion and retry batch; late retired-epoch rejection; health and cache-generation events; metrics; cleanup. Out of scope: UDP relay, DoH, physical DNS, recursive server behavior, resolver UI, cache storage, query-name logging, lanes, reconnect, independent per-query endpoint selection, and production numeric constants not accepted by TASK-260721-3miqh4.

## Acceptance Criteria
1. Every upstream connection is opened through the authenticated SSH session to the generation-global active configured exit-side endpoint and never through a local physical socket; startup and later promotion attempt configured endpoints serially under one injected startup or logical deadline. 2. TCP framing handles partial reads and writes, coalesced frames, injected maximum message and aggregate byte limits, EOF, timeout, cancellation, and hostile data with validated fixed bounds; admission reserves request, maximum response, framing, metadata, retry-batch, and queued bytes according to DNSRuntimePolicyV1. 3. One connection epoch owns unique upstream IDs and canonical question correlation for all admitted queries, permits bounded pipelining and out-of-order replies, never reuses an ID while live or tombstoned, rewrites the client ID only after validation, and allows exactly one terminal visible result per logical query. 4. A connection-fatal event atomically retires the epoch, ignores all late callbacks, leaves already terminal or cancelled queries terminal, fails expired queries, and places only retry-eligible QUERY operations into one admission-ordered batch; one coordinator, not individual queries, opens the next not-yet-attempted endpoint and replays each eligible query at most once there while new arrivals queue or fail within bounds. 5. A complete valid response including any RCODE never promotes or shops resolvers; cancellation cannot reopen work; transport or protocol exhaustion emits typed mandatory DNS health loss and cache-generation invalidation so the runtime stops admission and clears settings. Controlled fixtures cover multiple in-flight queries at EOF, malformed and mismatched responses, partial writes, one expired peer among live peers, cancellation tombstones, one promotion without reopen storms, late old-epoch replies, endpoint exhaustion, byte-pressure admission, cleanup, and zero physical fallback.
