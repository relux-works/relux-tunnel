# Least-privilege continuous integration and release quality gates

## Description
Establish credential-free pull-request validation and protected release orchestration for the generated Apple workspace, shared tunnel core, relay, repository specifications, security controls, versioning, and release evidence.

## Scope
In scope: GitHub Actions permission and trust boundaries, immutable action pins, untrusted-fork behavior, generated-project and legacy SwiftPM checks, shared-core and protocol tests, credential-free macOS target builds, relay release-matrix orchestration, board and specification validation, secret and dependency scanning, SBOM and notice gates, semantic version and release-note validation, protected GitHub Environments, serialized production jobs, artifact retention, and provenance metadata. Deferred boundary: iOS target definitions remain preserved but iOS build, TestFlight, App Store, and App Review workflows are inactive under ADR-024/027 and are not macOS required checks. Out of scope: issuing Apple credentials, implementing product features, defining relay protocol behavior, performing notarization or TestFlight uploads, and changing App Review or legal policy.

## Acceptance Criteria
1. Pull-request workflows run from a clean checkout with minimum read permissions, cannot read production environments or secrets, and report signing-required work as unavailable rather than passed. 2. Required checks deterministically validate generated-project drift, the preserved SwiftPM product, shared-core and protocol suites, active credential-free macOS targets, and declared relay targets; deferred iOS rows are reported as deferred and never inferred from macOS. 3. Board/specification, semantic version/tag, release-note, secret, dependency, license, SBOM, and third-party-notice gates fail on controlled negative fixtures. 4. Production release workflows use protected GitHub Environments, explicit least-privilege permissions, immutable action revisions, masked credentials, and concurrency that serializes release publication. 5. Every retained artifact records source commit, dependency lockfiles, toolchain and SDK versions, relay manifest and protocol version, bundle versions, signing identity metadata without private material, checksums, and retention class. 6. A CI threat and failure-path verification proves forks, reruns, cancellations, cache poisoning attempts, missing credentials, and partial releases cannot bypass required gates or leak secrets.
