# Integrate the libssh2 candidate adapter

## Description
Implement the libssh2 candidate adapter behind the revised M0-viability SSH transport contract, including nonblocking socket integration and bounded async adaptation, and build it in the macOS harness and the macOS provider configuration. libssh2 is the human-approved primary candidate (2026-07-28). The four semantics deferred to M3 are surfaced as explicit not-reported or unsupported states, never fabricated values, and never silent fallbacks.

## Scope
In scope: pinned libssh2 and crypto backend; extension-safe static or source build; session handshake; raw host-key access before authentication; approved public-key auth; direct-tcpip; bidirectional exec and exec/stdin upload; client-initiated rekey trigger; nonblocking EAGAIN integration; bounded buffers; deterministic cancellation and timeouts; keepalive; cheaply-available metrics; privacy-safe error mapping; allocator hooks where supported; macOS harness registration; macOS provider configuration build. Out of scope: iOS simulator and iPhone provider configurations (iOS deferred); consumer-driven receive-window credit semantics, RFC channel-open reason taxonomy, exact exec-exit metadata, and deep rekey/keepalive observability (all owned by the M3 task); NIOSSH fork work; masking an unsupported viability gate without a recorded decision; blocking calls on provider executors; SFTP; password prompts; ProxyJump; agent forwarding; production lane scheduling; candidate types outside the adapter.

## Acceptance Criteria
1. The adapter builds from pinned source with the approved crypto backend for the macOS harness and the macOS provider configuration and exposes no libssh2 type across the shared boundary. 2. Socket readiness and LIBSSH2_ERROR_EAGAIN are integrated without busy spinning or unbounded buffering, with deterministic cancellation and timeout behavior. 3. Raw host-key evidence before authentication, public-key auth, direct-tcpip, bidirectional exec, exec/stdin upload, EOF and half-close, keepalive, available metrics, and privacy-safe errors conform or are marked red with reproducible evidence. 4. Client-initiated rekey by byte and time threshold is proven through supported APIs of the accepted fork; the four M3-deferred semantics are emitted as explicit not-reported or unsupported states and are traceable to TASK-260728-3cveay. 5. Repeated connect and cancel smoke runs return sessions, channels, sockets, tasks, and custom allocations to baseline.
