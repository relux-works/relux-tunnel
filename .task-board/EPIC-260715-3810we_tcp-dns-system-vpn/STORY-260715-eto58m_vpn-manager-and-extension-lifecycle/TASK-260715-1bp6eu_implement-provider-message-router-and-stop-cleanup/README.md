# Implement provider message routing and deterministic stop cleanup

## Description
Implement the shared provider-side read-only v1 router and bounded cleanup owner defined by TASK-260715-1q4qhw. Both thin providers delegate messages and all start/stop/failure joining to this shared generation-safe implementation.

## Scope
In scope: four accepted read-only RuntimeCommand kinds; strict payload/version/request validation; one reply gate per non-nil handler; serialized generation snapshots; rejection of mutating RPC; raw Apple stop-reason capture/mapping; stop-wins-start; 10-second graceful cleanup budget; force-close of controllable handles; cancellation fan-out; late-callback retirement; provider-failure cancel handoff; privacy-safe diagnostics. Out of scope: arbitrary or mutating RPC, profile/trust/secret mutation, runtime business logic, unbounded export, reconnect, and platform-duplicated cleanup.

## Acceptance Criteria
1. Only getProtocolCapabilities, getRuntimeSnapshot, getCapabilities, and getDiagnostics are accepted in v1; every non-nil handler receives exactly one bounded response/error and no message can expose or mutate secrets/configuration. 2. Malformed, oversized, duplicate-key, unknown/future, duplicate, concurrent, nil-handler, and retired-generation inputs cannot crash, block, or update another generation. 3. Stop rejects new work, cancels start/runtime, joins accepted reverse cleanup, and completes every registered Apple stop gate once within the 10-second policy; expiry force-closes controllable handles and records a redacted deadline failure. 4. Stop during start completes the pending start gate with cancellation before stop gates; provider fatal failure calls cancelTunnelWithError once and the later system stop joins existing cleanup. 5. Shared tests run through both adapter seams and cover every Apple stop reason, every startup cancellation point, deadline, duplicate/late callbacks, route-clear uncertainty, deallocation, and 100-cycle baselines.
