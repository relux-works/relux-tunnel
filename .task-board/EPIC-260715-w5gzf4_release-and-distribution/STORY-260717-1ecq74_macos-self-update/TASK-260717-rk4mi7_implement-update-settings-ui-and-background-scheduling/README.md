# Implement macOS update settings and background scheduling

## Description
Add menu-bar-native macOS update controls around the accepted Sparkle lifecycle: persisted automatic-check preference, user-initiated Check for Updates, optional stable or pre-release channel selection, background scheduling, and deterministic presentation states. The production host must not steal focus and tests must use injected updater and scheduler seams without installing an update, publishing a feed, activating the system extension, or enabling VPN.

## Scope
In scope: ReluxProxyMac host-only settings/presentation model; persisted non-secret preferences; Sparkle updater configuration and check-now command; injectable scheduler and updater seams; stable/pre-release channel policy only when metadata enables it; localizable English copy through the repository localization path; deterministic Swift Testing coverage for idle, checking, up-to-date, available, downloading, failed, schedule, relaunch, and disabled-automatic-check behavior; focused macOS build and tests. Out of scope: update installation, signed appcast generation/publication, private EdDSA material, Developer ID/notary ceremony, provider changes, system-extension activation, VPN connection, route/DNS changes, iOS, or physical update replacement validation.

## Acceptance Criteria
1. The macOS host exposes non-focus-stealing menu-bar update settings for automatic checks, Check for Updates, and channel selection only when the configured feed policy enables pre-release updates. 2. Automatic-check and channel preferences persist across lifecycle reconstruction without storing secrets, and the accepted Sparkle controller receives the effective values through a narrow host-only adapter. 3. Check for Updates invokes the injected updater exactly once and background scheduling is deterministic, cancel-safe, idempotent, and suppressed when automatic checks are disabled. 4. A presentation model maps updater lifecycle events to idle/checking/up-to-date/available/downloading/failed states with localizable English copy and no raw URL, signature, key, path, or error-secret leakage. 5. Swift Testing covers persistence, channel gating, check-now, scheduling/cancellation/relaunch, every presentation state, and failure redaction; focused ReluxProxyMac tests and a host build pass without network installation or VPN/system-extension activation.
