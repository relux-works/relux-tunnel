# Integrate full-mode DNS over the UDP relay

## Description
Connect the existing tunnel-owned DNS transaction layer to priority relay associations for full-mode UDP resolution, using the approved exit resolver and retaining the existing SSH DNS-over-TCP path for truncation and safe fallback.

## Scope
In scope: consume the approved resolver identity, M1 DNS listener, cache, and TCP manager; relay UDP to the generation-global active IPv4 or IPv6 endpoint; DNS-priority association policy; UDP response correlation; EDNS and negotiated datagram cap; client transport semantics; exactly enumerated same-endpoint TCP retry triggers; handoff to M1 TCP connection and promotion ownership; shared logical deadline, byte, time, and retry accounting from DNSRuntimePolicyV1; cancellation; cache and health events; no physical resolver; metrics without query names. Out of scope: choosing a new resolver, parsing or caching anew, DoH, recursive resolution, fake DNS, general UDP admission, physical-interface sockets, response-based resolver shopping, and logging questions or answers.

## Acceptance Criteria
1. Client TCP DNS enters the existing listener and goes directly to the M1 SSH TCP manager; eligible client UDP DNS makes at most one relay UDP transmission to the active configured endpoint, and no DNS path opens a physical socket or invokes a device resolver. 2. A complete valid non-truncated UDP response, including any RCODE, is authoritative and ends the logical query without endpoint promotion; transaction ownership preserves IDs, EDNS, DNSSEC transparency, cache semantics, cancellation, and exactly one visible client result. 3. M2 owns a same-endpoint protocol retry from UDP to TCP only after TC=1, a local or negotiated relay-datagram size failure before a valid response, UDP response timeout, or a typed relay association or session transport failure; malformed or mismatched UDP data is rejected and does not trigger resolver shopping. 4. The same logical deadline and accounting allow at most one UDP attempt plus at most one TCP attempt per configured endpoint: M1 owns TCP connection reuse and may promote serially to each later not-yet-attempted endpoint only after TCP transport or protocol failure, never after a valid DNS response. 5. Controlled fixtures cover IPv4 and IPv6 endpoints, UDP success, TC, local oversize, timeout, association error, relay loss, client TCP, same-endpoint TCP recovery, later-endpoint TCP promotion, malformed UDP rejection, cache hit and miss, cancellation, priority and byte pressure, query-name-free metrics, one visible answer, and zero physical sentinel observations.
