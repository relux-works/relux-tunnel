# Implement the candidate-neutral SSH transport contract

## Description
Translate the reviewed TASK-260715-2ny6z4 contract into public Sendable Swift types and protocols in ReluxTunnelCore so both engine adapters and one shared conformance suite compile against the same lifecycle, channel, window, rekey, keepalive, error, metric, privacy, and dependency-injection semantics.

## Scope
In scope: type-erased factory and dependencies; connection and channel state values; pre-auth host-key policy evidence; public-key auth outcomes; direct-tcpip endpoints; exec and exec-stdin upload types; bounded partial-write/read/EOF/half-close/reset/cancel/close surface; per-channel receive-window policy and snapshots; byte/time/manual/server rekey controls and events; keepalive; timeout policy; stable errors; lane identity; schema-v1 metrics/events; focused Swift Testing compile and semantic contract fixtures. Out of scope: either concrete engine adapter, engine selection, NIOSSH fork internals, libssh2 packaging, production lane scheduling, flow migration, relay framing, SFTP, ProxyJump, UI, Keychain implementation, server fixtures, physical scale runs, and final numeric constants.

## Acceptance Criteria
1. ReluxTunnelCore exposes the complete reviewed candidate-neutral interface without importing or naming ReluxNIOSSH, SwiftNIO, libssh2, OpenSSL, or adapter types. 2. The type and dependency shape makes raw host-key bytes, algorithm, and SHA-256 fingerprint policy input before credential access or authentication, and represents every required host/auth outcome. 3. Direct-tcpip and exec channels expose bounded partial writes, reads, stdout/stderr and exit results, EOF and half-close, reset, cancel, idempotent close, exec-stdin upload, and independently observable capped receive windows. 4. Injected clock and policy types expose automatic byte/time rekey, explicit production-path trigger, server rekey, keepalive, cancellation/timeouts, typed events, and schema-v1 privacy-safe metrics exactly as the reviewed contract defines. 5. Swift Testing fixtures verify invalid states and policy validation, candidate-type erasure, stable error mapping/data shape, metric/event schema, and secret/destination/command exclusion; the package boundary checks and core build pass.
