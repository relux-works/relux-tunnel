| ADR-028 | Accepted | **One human permission ceremony is one board node, and a human node is never counted as autonomous.** (a) *Ownership.* `TASK-260728-q5kjta` owns Ceremony C1 and is the only up-front human-input node. The evidence tasks it unblocks (`TASK-260715-apc34w`, `TASK-260715-3jloqy`, `TASK-260728-dveo1o`, `TASK-260717-ziprhs`) are agent work that runs unattended with the granted access and keeps its full evidence obligations. Spreading the permission ceremony across several tasks forces the human to re-appear after producer-reviewer routing, which is what the round-2 review rejected. (b) *Labelling.* A task whose completion requires a human action or decision is a **human node** — a scheduler barrier that is never counted in an autonomous total, even when agent work follows inside the same node. Tasks that merely consume access or a decision granted earlier are autonomous and are reported as that node's follow-up. (c) *Later-artifact rule.* An approval that acknowledges a not-yet-existing artifact cannot be pre-granted: Approval A1 (`TASK-260715-9yp8to`), sign-off S1 (`TASK-260715-2ayxqn` AC5), the manual ratification checkpoints (`TASK-260717-1dsqnj`, `TASK-260717-l639qp`, `TASK-260717-2d308k`), and the release-candidate approvals (`TASK-260715-1r48pc`, `TASK-260715-yynqbr`, `TASK-260715-2aessv`) are therefore separate, later interactions, not C1 content. (d) *Resumed evidence amendment, owner-approved 2026-08-10.* One ceremony node does not require one continuous sitting. C1 may combine resumed owner interactions with producer/reviewer work between them when the record states that provenance and does not invent uninterrupted-session boundaries, a historical Always Allow click, or separately timestamped two-factor completion. Acceptance rests on effective prompt-free access for the named signing identities/tools, an authenticated Relux Works portal/team session and confirmed matrix authority, named Keychain-backed notarization and Sparkle custody, and a privacy scan finding zero secret values or secret paths in repository, board resources, run logs, and shell history. Harmless command-name-only history is permitted; secret-bearing command arguments, credential input, key identifiers, account credentials, key bytes, and secret paths remain prohibited. |

## Decision rationale

The accepted decisions preserve the product invariant that device-to-exit
payload transport is SSH while avoiding TCP-over-TCP for application TCP. They
also keep the iOS extension memory budget and public-API boundary ahead of code
reuse convenience.

Open items are deliberately concentrated in M0. No implementation task may
silently resolve them through a local workaround; the evidence and selected
tradeoff must update this log.

ADR-023 and ADR-024 narrow *when* evidence is owed, not *whether*. Three rounds
of pinned-source analysis showed that the original full-fidelity M0 contract
required semantics no public SSH library exposes, so every candidate needed
open-ended fork surgery before any client could run. Splitting the contract into
a viability tier and an evidence-gated M3 tier restores a working macOS client
path without weakening host-key-before-auth, Keychain-only secrets, fail-closed
DNS, bounded memory, the public PacketFlow bridge, the rootless exec/stdio
relay, or the signed/notarized release requirements.
