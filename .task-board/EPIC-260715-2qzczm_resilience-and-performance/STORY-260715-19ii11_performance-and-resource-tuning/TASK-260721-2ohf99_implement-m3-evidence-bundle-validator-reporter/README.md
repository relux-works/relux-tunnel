# Implement the M3 evidence bundle validator and statistical reporter

## Description
Implement a versioned offline validator and deterministic reporter for the TASK-260715-2kchi0 protocol. It validates row and bundle schema, authority state, content-addressed raw references, privacy and redaction declarations, safety-gate evidence, immutable red or unavailable rows, paired baseline comparisons, fixed bootstrap intervals, practical-effect thresholds, and accepted baseline or configuration updates before any M3 result is consumed.

## Scope
In scope: canonical JSON and schema validation; protocol/source/dependency/config hashes; required available or unavailable metric fields; artifact existence, byte length, SHA-256, privacy class, capture authorization and redaction metadata; duplicate and missing row detection; baseline and candidate pairing by device and seed; deterministic 10000-resample intervals and multiplicity coverage; material improvement, neutral pass, regression, insufficient precision and safety-red outcomes; exclusion and rerun linkage; immutable manifest and summary output; failure-safe CLI/library integration for the SPM harness; fixtures and negative tests. Out of scope: collecting metrics, generating traffic, applying impairments, running physical benchmarks, selecting production parameter winners, uploading telemetry, reading restricted raw captures, changing protocol thresholds, or converting red or unavailable rows to pass.

## Acceptance Criteria
1. The validator accepts only protocol-v1 rows and bundles that contain every required device, environment, revision, server, algorithm, profile, policy, parameter, traffic, impairment, schedule, metric, counter, raw-reference, privacy, authority, gate and review field, with explicit unavailable objects rather than omitted or guessed values. 2. Artifact validation verifies bundle-relative logical references, byte lengths and SHA-256; requires capture authorization, privacy class, retention and redaction evidence; rejects absolute user paths, prohibited fields, unreferenced files, missing restricted-custodian metadata and manifest mutation. 3. The reporter pairs baseline and candidates by device, row and fixed seed, applies the protocol deterministic bootstrap, multiplicity and practical-effect rules exactly, preserves every valid, red, invalid and unavailable input, and emits material-improvement, neutral-pass or explicit red classifications without post-hoc samples or thresholds. 4. Safety failures for bytes, ordinary DNS fallback, routes, resource or memory bounds, failure behavior, nominal drops, collector overflow or cleanup always produce red and cannot be outweighed by performance or energy; provisional and production-authorized states remain separate. 5. Automated positive, boundary and hostile fixtures cover missing and unknown fields, equality and one-over limits, corrupt hashes, duplicate rows, unauthorized captures, redaction failures, exclusions, reruns, unavailable metrics, zero baselines, noisy comparisons, regressions, safety red rows, deterministic replay and immutable accepted-update lineage, and publish task-scoped verification evidence.
