# Compose M0-bound runtime sessions behind production factories

## Description
Implement the production dependency factories consumed by ReluxTunnelCore using only the accepted M0 binding manifest from TASK-260720-1qhxqa. For each provider, construct candidate-neutral SSH bootstrap and transport, TCP and DNS consumers, an M1PacketPlaneSession wrapper over the accepted PacketBridge API, PacketFlow, NetworkSettingsPlanBuilder and NetworkSettingsApplier, clocks, metrics, logging, cancellation, memory pressure, and snapshot dependencies. M1PacketPlaneSession.prepare is pure preflight that validates bound configuration and constructs references without acquiring descriptors, HEV resources, the private SOCKS boundary, or PacketFlow reads. Its post-settings activateReads invokes the existing PacketBridge.start and owns the resulting HEV/private-ingress/bridge lifetime. Preserve deterministic harness substitution and prevent provider, HEV C, or selected-engine types from entering coordinator contracts.

## Scope
In scope: binding-manifest schema and digest validation; productionCompositionPermitted enforcement; factory and session protocols; one object graph per runtime generation; pure packet-plane preflight; post-settings activation through the accepted PacketBridge.start API; private-ingress dispatch to TCP CONNECT and virtual-DNS UDP/TCP with other UDP rejected in M1; health and idempotent stop; ownership transfer and reverse release; native library startup and shutdown hooks; accepted dependency pins and configuration values; iOS, macOS and harness compositions; compile-time boundary guards; fail-fast behavior before routes for absent, superseded or incompatible bindings. Out of scope: changing PacketFlowBridge startup semantics, generating or reinterpreting M0 decisions, choosing or tuning engines, MTU, buffers or windows, coordinator transitions, TCP/DNS internals, route policy values, UI, general UDP, lanes and reconnect.

## Acceptance Criteria
1. iOS and macOS production roots plus the deterministic harness root satisfy the same candidate-neutral session interfaces, while only production roots require a valid TASK-260720-1qhxqa binding manifest. 2. Each generation creates packet, HEV, SSH, TCP and DNS objects at most once; M1PacketPlaneSession.prepare acquires no descriptor, HEV lease/thread, private listener or PacketFlow read, activateReads separately invokes the accepted PacketBridge.start after settings, and stop releases every acquired object in the contract order. 3. A production root fails before routes when productionCompositionPermitted is false, an accepted resource digest or pin differs, a binding is superseded, or a mandatory capability is absent; no local default or task note can substitute. 4. No selected-engine type, HEV C API, NEPacketTunnelProvider, NEPacketTunnelFlow implementation, host-app object or live platform callback crosses an unintended shared boundary. 5. iOS provider, macOS provider and harness compile/smoke tests prove exact bound component resolution, pure preflight, post-settings start, DNS-only UDP dispatch, deterministic substitution, repeated cleanup and boundary-guard rejection of type leakage.
