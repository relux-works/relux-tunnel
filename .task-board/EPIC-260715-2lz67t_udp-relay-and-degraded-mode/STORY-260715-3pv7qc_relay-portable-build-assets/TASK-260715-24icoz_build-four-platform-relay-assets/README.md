# Build the four declared portable relay assets

## Description
Produce the bundle-ready relay binaries for macOS arm64 and macOS x86_64 using the pinned path, with unique names, verified machine types, declared linkage, and target-baseline execution evidence. Linux x86_64 and Linux arm64 assets are still built and retained, but their native execution evidence is deferred to the release path with the Linux CI runner and must not block the macOS prototype.

## Scope
In scope: clean release-mode builds for all four declared tuples; protocol-enabled relay source; unique normalized file names; executable permissions for staging; binary architecture and format inspection; strip and debug-symbol policy; minimum macOS and Linux or libc compatibility; linkage inventory; measured byte sizes; macOS arm64 native and approved Rosetta darwin/amd64 controlled smoke; artifact retention and hashes. Out of scope: native Linux execution evidence and native-Intel execution evidence (deferred to TASK-260715-1c4l9v on the release path with the Linux runner); ratifying the shipping bundle byte budget (owned by TASK-260715-1tzaed); universal binaries unless explicitly chosen; application bundle manifest; remote upload; code signing or notarization; Docker images as product artifacts; UDP end-to-end traffic; unsupported operating systems.

## Acceptance Criteria
1. Exactly one nonempty executable is produced for each declared OS and architecture tuple and automated inspection confirms its binary format and machine architecture. 2. Asset names, protocol version, build mode, minimum runtime, dynamic library requirements, and debug-symbol disposition are unambiguous and recorded. 3. The macOS arm64 native and approved Rosetta darwin/amd64 assets start and exit successfully as an unprivileged user and report the expected build identity; Linux and native-Intel execution rows are recorded as explicitly deferred to TASK-260715-1c4l9v, not as passes. 4. Measured total and per-asset byte sizes are recorded and handed to TASK-260715-1tzaed for shipping-budget ratification. 5. Build logs and retained artifacts contain no developer paths, credentials, signing material, real host data, or undeclared runtime dependencies.
