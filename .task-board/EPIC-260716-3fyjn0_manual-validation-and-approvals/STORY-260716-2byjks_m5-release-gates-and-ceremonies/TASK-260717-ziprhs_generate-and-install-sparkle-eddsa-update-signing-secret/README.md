# TASK-260717-ziprhs: generate-and-install-sparkle-eddsa-update-signing-secret

## Description
Record the Sparkle EdDSA update-signing key evidence and custody. The ed25519 keypair is generated and the PRIVATE key is placed into approved custody once inside Ceremony C1 (TASK-260728-q5kjta), alongside the Developer ID and notarization credentials. This task runs unattended afterwards and records the PUBLIC key, its fingerprint, the tool version, the generation date, and the custody location by name only, plus the rotation and revocation procedure. It deliberately stops there: pinning SUPublicEDKey, wiring the CI signing secret, and verifying a signed appcast are owned by TASK-260728-3bj9bk, because the generated macOS target, the updater integration, and the appcast pipeline do not exist yet. Completing this task does not mean self-update signing works.

## Scope
In scope: verifying that the keypair generated at Ceremony C1 exists and that the private key resides only in the approved custody store; recording the public key, its fingerprint, the pinned Sparkle vendor tool version, and the generation date as non-secret evidence; the rotation and revocation procedure for this keypair; a leak scan. Out of scope: generating the keypair or moving the private key (TASK-260728-q5kjta owns the ceremony); editing any Info.plist or project manifest; creating or binding CI secrets; signing or verifying an appcast; publishing release assets; any claim that the updater integration or CI signing path is complete.

## Acceptance Criteria
1. The keypair generated at Ceremony C1 is confirmed present and the pinned Sparkle vendor tool version and generation date are recorded. 2. The private key resides only in the approved custody store; it is absent from git, board resources, shell history, and logs, and its bytes are never echoed. 3. A TASK-ID-scoped outcome records the public key value and fingerprint, the custody location by name only, and the rotation and revocation procedure. 4. The outcome states explicitly that SUPublicEDKey pinning and appcast signing verification remain open under TASK-260728-3bj9bk and are not evidenced here. 5. A post-run scan of the repository, board resources, and run logs finds no private key material.
