# Generated-project developer workflow

This is the developer entry point for the generated Apple project and its
coexistence with the legacy SwiftPM product. The architecture authority is the
[generated-project ADR](TASK-260715-32umrc_generated-project-architecture-adr.md);
the operational safety authority is the [build-host policy](build-host-safety.md).

The Apple workspace is generated by Tuist 4.202.5, pinned in `mise.toml`.
`Workspace.swift`, `Project.swift`, `Tuist.swift`, `Package.swift`, and
`Configuration/*.xcconfig` are reviewed inputs. The ignored generated
`ReluxTunnel.xcworkspace` and `ReluxTunnelApp.xcodeproj` are disposable output:
never edit or commit them.

## Build-host boundary

This development Mac is build-only. The commands in the credential-free and
harness sections below are allowed. On this host, do **not** sign, install, or
launch the app or provider; save or remove a VPN preference; activate a system
extension; call `startVPNTunnel`; or change routes, interfaces, packet-filter
rules, or DNS. Do not run the separate Gate P0 probe here.

Signed physical-VPN validation belongs only to the dedicated Mac gate
`TASK-260819-25e1ys`, after its human provisioning prerequisite and
`scripts/physical-test-host-preflight.sh` pass. A successful build, unit test,
harness smoke, archive inspection, or unsigned provider build does not replace
that gate.

## Prerequisites and clean-checkout validation

Use a macOS build host with Git, GNU Make, Python 3, curl, Mise, Xcode command-line
tools capable of loading the Swift tools 6.1 manifest, and the SDKs selected by
Xcode. The active generated products target macOS 15.0; iOS 18.0 is a checked-in
but deferred package/platform input. Repository pins are Tuist 4.202.5, Go
1.26.5, and Syft 1.48.0. The accepted clean-clone matrix used macOS 26.5,
Xcode 26.5, Swift 6.3.2, and Mise 2026.2.0; CI uses the arm64 `macos-15` runner
and installs Mise 2026.3.10 with the commit and checksum pinned in
`.github/workflows/ci.yml`.

Keep the v2 and legacy repositories separate. From a directory that will hold
both checkouts:

```bash
git clone https://github.com/relux-works/relux-tunnel.git
git clone --branch v0.1.0 --single-branch \
  https://github.com/relux-works/relux-proxy.git
cd relux-tunnel
git -C ../relux-proxy verify-tag v0.1.0
mise trust "$PWD/mise.toml"
make credential-free-validate LEGACY_ROOT="$PWD/../relux-proxy"
```

`mise trust` is required for a fresh checkout. The accepted clean-clone run
proved that omitting it fails before acceptance. The umbrella command installs
the exact Tuist pin through Mise, downloads and checksum-verifies the pinned
host Go/Syft archives, builds and verifies the relay Apple bundle input,
generates the workspace twice, builds every active macOS host/provider scheme in
unsigned Debug and Release, runs the generated target tests and shared Swift
tests, performs a Swift release build, validates native packaging and dependency
direction, and validates a disposable detached copy of legacy v0.1.0. It never
performs signing or Network Extension lifecycle work.

Logs for the umbrella gate are under
`.temp/TASK-260715-sbrrp7/credential-free-validation/`: `summary.log`,
`environment.log`, and `logs/*.log`. The environment record contains only
public tool/SDK/revision metadata and never dumps the process environment or
signing inputs.

## Individual generation, build, test, and smoke commands

Run these from the repository root after `mise trust "$PWD/mise.toml"`.

```bash
# Generate after removing only the disposable workspace/project.
make workspace-generate

# Generate twice and verify deterministic files, graph, schemes, settings,
# ignored outputs, and an unchanged Package.swift/worktree.
make workspace-validate

# Unsigned Debug/Release host and provider builds plus both generated test bundles.
make macos-targets-validate

# Shared SwiftPM boundary, packaging, tests, and Debug build.
make validate-core

# The exact shared suite and Release build used by the clean-checkout matrix.
swift test
swift build -c release
```

The active workspace-visible scheme set is exactly `ReluxProxyMac`,
`ReluxProxyMacTunnel`, `ReluxProxyMacUITests`, `ReluxProxyIOSUITests`,
`ReluxTunnelCore`, `ReluxTunnelHarness`, `relux-relay`, and
`relux-relay-protocol-test`. Only `Debug` and `Release` configurations exist.
The two relay scheme names are stable discovery surfaces; Go build and smoke
ownership remains in the explicit Make targets, not an implicit Xcode build
phase. The production iOS schemes and targets are not generated in
`.macOSOnly` mode; `ReluxProxyIOSUITests` owns only the isolated Simulator
fixture described in [Apple UI-test validation](apple-ui-test-validation.md).

The harness smoke is a local no-op resource-lifecycle test. It does not import
or invoke Network Extension:

```bash
swift run ReluxTunnelHarness smoke --configuration-json \
  '{"schemaVersion":1,"seed":42,"sourceRevision":"local","dependencyRevisions":{},"profileReference":{"value":"11111111-1111-1111-1111-111111111111","privacy":"sensitive"},"parameters":{"mode":{"value":"noop","privacy":"public"}}}'
```

The result is one sorted-key JSON document on stdout; sensitive values are
rendered as `<redacted>`. The harness suite is `swift test --filter
ReluxTunnelHarness`. SwiftPM build products are below `.build/`; harness and
other task-scoped logs belong below `.temp/`.

For relay packaging, reproducibility, verification, and shell smoke, use the
same inputs as the umbrella gate:

```bash
./scripts/bootstrap-relay-tools.sh
RELAY_VERSION="$(sed -n 's/^MARKETING_VERSION = //p' Configuration/Versions.xcconfig)" \
SOURCE_COMMIT="$(git rev-parse HEAD)" \
SOURCE_DATE_EPOCH="$(git show -s --format=%ct HEAD)" \
make relay-shell-validate
```

The release-builder result is staged under `.build/relay/apple-bundle-input/`.
The separate trusted application bundle is deterministically materialized from
the accepted four-asset board resource under `.build/relay/relay-assets-v1/` by
`make relay-asset-bundle-generate`; `make relay-asset-bundle-check` verifies its
schema, exact file set, bytes, identity, provenance, and generated Swift lookup.
Protocol test binaries are under `.build/relay/protocol-tests/`; isolated build
state is under `.build/relay/work/`. No relay command uploads or installs an
executable on an SSH host.

For the four credential-isolated cross-builds, first provision the official
host archive as documented in [`relay/README.md`](../relay/README.md), then run:

```bash
export RELAY_VERSION="$(sed -n 's/^MARKETING_VERSION = //p' Configuration/Versions.xcconfig)"
export SOURCE_COMMIT="$(git rev-parse HEAD)"
export SOURCE_DATE_EPOCH="$(git show -s --format=%ct HEAD)"
make relay-build-darwin-amd64 RELAY_VERSION="$RELAY_VERSION" SOURCE_COMMIT="$SOURCE_COMMIT" SOURCE_DATE_EPOCH="$SOURCE_DATE_EPOCH" RELAY_BUILD_CLEAN_FLAG=--require-clean
make relay-build-darwin-arm64 RELAY_VERSION="$RELAY_VERSION" SOURCE_COMMIT="$SOURCE_COMMIT" SOURCE_DATE_EPOCH="$SOURCE_DATE_EPOCH" RELAY_BUILD_CLEAN_FLAG=--require-clean
make relay-build-linux-amd64 RELAY_VERSION="$RELAY_VERSION" SOURCE_COMMIT="$SOURCE_COMMIT" SOURCE_DATE_EPOCH="$SOURCE_DATE_EPOCH" RELAY_BUILD_CLEAN_FLAG=--require-clean
make relay-build-linux-arm64 RELAY_VERSION="$RELAY_VERSION" SOURCE_COMMIT="$SOURCE_COMMIT" SOURCE_DATE_EPOCH="$SOURCE_DATE_EPOCH" RELAY_BUILD_CLEAN_FLAG=--require-clean
```

Outputs are below `.build/relay/portable/<os>-<arch>/`. Cross-built Linux
binaries are not executed on macOS; native unprivileged Ubuntu 24.04 amd64 and
arm64 smoke is a CI-owned row. No older Linux-kernel compatibility or macOS
runtime result follows merely from a successful cross-build.

Validate the independent legacy lane explicitly with the sibling checkout still
detached at v0.1.0:

```bash
make check-legacy LEGACY_ROOT="$PWD/../relux-proxy"
make test-legacy-guard LEGACY_ROOT="$PWD/../relux-proxy"
swift test --package-path "$PWD/../relux-proxy"
swift build -c release --package-path "$PWD/../relux-proxy"
```

The guards require signed tag `v0.1.0` at
`2557aba1c030d0643d76e0bc3b185f6d5fd172e1` and do not modify the supplied
checkout. See [legacy preservation](legacy-preservation.md).

## Signing inputs without secrets

`Configuration/Identity.xcconfig` is the checked-in, non-secret projection of
Gate P0 matrix `2026-07-28.r12`. Its development team is `262RZ595FP`; macOS
bundle IDs are `works.relux.tunnel.mac` and
`works.relux.tunnel.mac.tunnel`. `Configuration/Signing.example.xcconfig`
contains the non-secret Apple Development selector, target-specific profile
specifier names, and development entitlement-file paths.

Credential-free builds keep `CODE_SIGNING_ALLOWED=NO` and
`CODE_SIGNING_REQUIRED=NO`; they do not query identities or profiles. An
authorized human or credentialed CI lane obtains certificates and provisioning
profiles from the Relux Works Apple Developer account and installs/imports them
into that lane's protected Keychain/profile store. Developers and agents must
not inspect, export, print, copy, or record those credential bytes or their
private filesystem locations.

For an explicitly authorized credentialed machine, copy only the public schema
to ignored `Configuration/Signing.local.xcconfig` and supply selectors there or
through protected CI injection. Never put certificates, private keys, profile
contents, passphrases, notarization keys, tokens, or Keychain paths in an
xcconfig, manifest, shell command, log, board resource, or commit. The overlay
is ignored and is deliberately absent from generated project files. Its
presence never authorizes signing on this build host.

SSH runtime credentials follow a separate boundary: configuration carries only
opaque references. Private keys and passphrases are created/imported by the
product's approved UI and remain in the platform Keychain described by
`.spec/security-privacy.md`; they are not developer build inputs.

## Generated files and dependency updates

Edit checked-in authorities, regenerate, and commit only reviewed inputs and
deterministic generated protocol/native artifacts that their owning workflow
requires. Do not hand-edit Xcode project/workspace state, relay staging output,
SwiftPM/Tuist caches, DerivedData, `.temp/`, or the signing overlay.

- Workspace/target changes: edit `Project.swift`, `Workspace.swift`, Tuist
  configuration, sources, target-owned plist/entitlement inputs, or xcconfigs;
  run `make workspace-validate`, then `make macos-targets-validate`.
- Relay protocol changes: edit `Protocol/Relay/relay-v1.schema.json`; run
  `make relay-protocol-generate`, `make relay-protocol-vectors-generate`, and
  `make relay-protocol-check`. Never hand-edit generated Swift/Go bindings.
- HEV/native artifact changes: update the exact revision, recursive source
  hashes, flags, slices, licenses, notices, rebuild command, and artifact hashes
  in `NativeDependencies/manifest.json`; rebuild from a disposable verified
  source checkout using `native-dependency-tool.py`; run `make validate-native`.
  Follow [native dependency packaging](native-dependency-packaging.md).
- libssh2/OpenSSL changes: update the audited archives/pins and the allowlisted
  Relux patch/provenance docs; rebuild with `make build-libssh2
  LIBSSH2_SOURCE_ARCHIVE=/path/to/audited-libssh2.tar.gz
  OPENSSL_SOURCE_ARCHIVE=/path/to/audited-openssl.tar.gz`; run
  `make test-libssh2-source-gates` and `make validate-libssh2`.
- ReluxNIOSSH changes: use a clean disposable worktree and follow
  `Dependencies/ReluxNIOSSH/REBASE.md`; update `UPSTREAM.md`,
  `PATCH_MANIFEST.json`, the checked-in lock, and exact patch allowlist; run
  `make validate-reluxniossh` and its documented formatting gate.
- Relay toolchain changes: update `relay/toolchain-manifest-v1.json` and its
  code-owned contract together; provision only official archives whose names and
  hashes match the new reviewed manifest; run `make relay-toolchain-ci` and the
  applicable native smoke rows. Builds never fetch modules or toolchains.

Unpinned ranges, branches, local replacement directives, opaque binary swaps,
runtime downloads, unreviewed dynamic libraries, and dependency changes that
silently raise the macOS 15/iOS 18 floor are prohibited.

Common failures are fail-closed:

- Mise reports the checkout as untrusted: run `mise trust "$PWD/mise.toml"`
  from the repository root, then retry. Do not bypass Mise with global Tuist.
- `LEGACY_ROOT` or v0.1.0 fails: supply a separate Git checkout with tags;
  verify `v0.1.0`; do not point it at this repository or edit the baseline.
- Relay tool/archive missing or mismatched: use
  `./scripts/bootstrap-relay-tools.sh` for the credential-free lane, or supply
  the exact official archive named by `relay/toolchain-manifest-v1.json` for
  offline provisioning. Do not disable checksum/provenance checks.
- Relay Apple input missing/tampered: rerun relay bootstrap and
  `relay-shell-validate`; do not remove the provider resource or edit its
  manifest/checksum file.
- Generated graph or hash drift: discard only the ignored project/workspace by
  rerunning `make workspace-generate`; make the real fix in checked-in inputs.
- Signing/profile lookup appears in a credential-free build: remove local
  signing overrides from that invocation and verify the ignored overlay is not
  referenced by generated state. Never “fix” an unsigned lane by selecting an
  identity.
- A physical-VPN, install, launch, route, or DNS step appears necessary: stop on
  this host and route the work through `TASK-260819-25e1ys`; do not convert the
  local build lane into a physical test.

## What the current evidence does and does not prove

Accepted `TASK-260715-nphtib` clean-clone evidence proves deterministic
generation; exact macOS targets/schemes; unsigned Debug/Release host/provider
builds; generated and shared tests; provider linkage to the macOS adapter, HEV,
and libssh2; relay four-target packaging/checksums/SBOMs and shell smoke;
credential-free harness smoke; and detached legacy SwiftPM validation. Packet
bridge, SSH contracts/selected adapter, relay protocol/shell, and provider
composition are therefore implemented and build- or test-validated to those
specific boundaries.

It does **not** prove a signed containing app/system extension, installation,
provider launch, saved VPN preference, physical packet flow, real-host SSH/relay
session, routing or DNS behavior, Developer ID archive, notarization, DMG,
release publication, or any iOS target. Those rows were explicitly **NOT RUN**.
This repository must not be described as shipping a validated VPN until the
dedicated signed physical gates and downstream release gates pass.

Migration is also a non-goal: v2 does not absorb, rename, rewrite, or retire the
legacy `ReluxProxy` sources, defaults, `/usr/bin/ssh` behavior, bundle identity,
packaging, or release history. No defaults/profile conversion, artifact-name
takeover, rollback, uninstall, EOL, or user migration is authorized without a
separate approved migration decision.
