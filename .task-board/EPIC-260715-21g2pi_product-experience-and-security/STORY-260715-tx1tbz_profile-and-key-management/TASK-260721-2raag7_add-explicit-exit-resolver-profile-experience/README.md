# Add the explicit exit-resolver profile experience on iOS and macOS

## Description
Deliver one cross-platform M4 profile slice for configuring the approved ordered numeric exit-side DNS endpoints and remediating legacy profiles that cannot connect until a resolver is supplied.

## Scope
In scope: shared presentation state and actions; editing, adding, removing, and reordering a non-empty endpoint list within the accepted endpoint-count policy from TASK-260721-3miqh4; IPv4 and IPv6 literal plus port entry; port 53 presentation default; field-level validation; requiresResolverConfiguration remediation; repository publication and revision conflicts; active-profile safeguards; iOS and macOS SwiftUI surfaces; accessibility identifiers; snapshots; Page Object UI tests. Out of scope: changing TASK-260715-1tnjlu policy, selecting or prefilling a public resolver, hard-coding an unevidenced count ceiling, hostname endpoints, DoH, exit-host discovery, DNS transport implementation, final marketing copy, and physical leak validation.

## Acceptance Criteria
1. The shared editor and both Apple surfaces present a required ordered list of numeric resolver endpoints with address and port controls, enforce the accepted DNSRuntimePolicyV1 endpoint-count ceiling, default an omitted port to 53, and never prefill a product, physical, public-vendor, loopback, or discovered resolver address. 2. Validation and normalized save values exactly match TASK-260721-33o8fc and TASK-260721-3miqh4, including deliberate loopback, private, and ULA support and field-specific errors for hostnames, zones, invalid families, duplicates, empty or policy-oversized lists, and ports. 3. A legacy profile without dnsResolver remains visible with requiresResolverConfiguration remediation, cannot be selected for a new connection until valid input is saved, and is never silently upgraded from system DNS. 4. Add, remove, reorder, save, discard, relaunch, concurrent revision conflict, selected-profile change, active-profile edit, and endpoint-count boundary paths produce deterministic repository generations and accessible recovery on iOS and macOS. 5. Swift tests, snapshots, and iOS and macOS Page Object journeys cover valid IPv4-only, IPv6-only, dual ordered, loopback, invalid, policy-count boundary, migration, and conflict states with stable identifiers, keyboard and VoiceOver behavior, screenshot inspection, and no DNS network dependency.
