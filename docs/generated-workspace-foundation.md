# Generated workspace foundation

The Apple workspace is generated by Tuist 4.202.5, pinned in `mise.toml`. The
checked-in manifests and configuration files are the authority; generated
`.xcodeproj` and `.xcworkspace` artifacts are ignored and must not be edited or
committed.

## Generate and validate

Trust the repository Mise configuration once, then generate from a clean state:

```bash
mise trust mise.toml
make workspace-generate
```

`scripts/generate-workspace.sh` installs and verifies the exact pinned Tuist
version before deleting only `ReluxTunnel.xcworkspace` and
`ReluxTunnelApp.xcodeproj` and regenerating them. It never invokes an unpinned
global Tuist.

Run the deterministic foundation gate with:

```bash
make workspace-validate
```

From a clean checkout, the complete credential-free local/PR gate is:

```bash
make credential-free-validate LEGACY_ROOT=/path/to/relux-proxy
```

Prerequisites are macOS with the repository's supported Xcode command-line
tools, Mise, Python 3, Git, Make, curl, and a read-only legacy checkout that
contains signed tag `v0.1.0`. The command installs the exact Tuist pin through
Mise and downloads only checksum-pinned Go/Syft archives from
`relay/toolchain-manifest-v1.json`. It runs the same entry point used by pull
requests: deterministic generation, exact target/scheme checks, unsigned
Debug/Release host and provider builds, shared Swift Testing suites, relay
smoke, native packaging/linkage checks, and the detached legacy SwiftPM
regression lane.

The pull-request job uses the arm64 `macos-15` image, bootstraps Mise 2026.3.10
through a commit-pinned action, and verifies the matching macOS arm64 binary
checksum before invoking that same Make target. A contract regression test
keeps the runner label and asset checksum paired. The action does not duplicate
tool installation policy: the repository entry point still installs and
verifies the Tuist version pinned in `mise.toml`.

Task-scoped, credential-free logs are written only below
`.temp/TASK-260715-sbrrp7/credential-free-validation/`. The environment record
contains the source revision, public tool/SDK versions, deployment targets,
and invoked schemes; it never dumps the process environment or signing inputs.
The summary explicitly reports credentialed signing and deferred iOS lanes as
`NOT RUN` with reasons.

Validate the macOS containing app, its exactly-one embedded packet-tunnel
system extension, both credential-free configurations, target-owned plists and
versions, and the Swift Testing contract suites with:

```bash
make macos-targets-validate
```

This target gate writes build and test logs under
`.temp/TASK-260715-uyju7n/`. Development signing remains an explicit Gate P0
lane: copy `Signing.example.xcconfig` to the ignored local overlay or inject the
same target-specific settings on the command line; generated Xcode state is
never edited.

The gate performs two clean generations, compares normalized generated file
hashes (excluding Tuist's expected per-user `xcuserdata`), checks the exact
Xcode-visible scheme list, verifies that `Package.swift` is unchanged, and
confirms that generation creates no tracked or unexplained untracked diff.
Task-scoped logs and hashes go to `.temp/TASK-260715-2btjwm/`.

## Inputs and conventions

- `Workspace.swift` owns the stable `ReluxTunnel.xcworkspace` name.
- `Project.swift` owns the `ReluxTunnelApp` project, the local `ReluxTunnel`
  Swift package reference, exactly `Debug` and `Release`, and the stable scheme
  names from the generated-project ADR. Automatic target and workspace schemes
  are disabled, so later target tasks extend the named schemes instead of
  creating unstable duplicates.
- The checked-in `workspaceMode` input is `.macOSOnly`. It emits exactly the six
  active macOS, package/harness, and relay wrapper schemes. The two stable iOS
  scheme names remain source-controlled in `deferredSchemeNames`, but are not
  generated or visible to `xcodebuild` in this mode.
- When ADR-024/ADR-027 are explicitly resumed, the iOS target task changes the
  checked-in input to `.macOSAndIOS` while adding the corresponding targets and
  scheme actions. Foundation schemes intentionally have no buildable actions;
  dependent target tasks attach their actions without renaming them.
- `Configuration/Base.xcconfig` owns Swift 6, complete strict concurrency,
  macOS 15.0, iOS 18.0, and credential-free signing defaults. Provider targets
  use `Provider-Debug.xcconfig` and `Provider-Release.xcconfig`, which add
  `APPLICATION_EXTENSION_API_ONLY=YES` without constraining containing apps.
- `Configuration/Versions.xcconfig` is the single checked-in version input for
  `MARKETING_VERSION`, integer `CURRENT_PROJECT_VERSION`, relay compatibility,
  and protocol version.
- `Configuration/Identity.xcconfig` is the non-secret projection of the
  accepted `2026-07-28.r12` identifier matrix. Targets consume these variables;
  source files do not repeat identifier literals.

Credential-free generation and builds use `CODE_SIGNING_ALLOWED=NO` and do not
look up an identity or provisioning profile. For an explicitly credentialed
lane, copy `Configuration/Signing.example.xcconfig` to the ignored
`Configuration/Signing.local.xcconfig` and provide only local or CI-injected
values. Never put profile contents, private keys, notarization credentials, or
other secrets in manifests, generated projects, logs, or board resources.

The root `Package.swift`, its `Sources/` and `Tests/`, relay sources, and native
dependencies remain independently owned inputs. Tuist references the package;
it does not copy, absorb, rewrite, or remove those files.
