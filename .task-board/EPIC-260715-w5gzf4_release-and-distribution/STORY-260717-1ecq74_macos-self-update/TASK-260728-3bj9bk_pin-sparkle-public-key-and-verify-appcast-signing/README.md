# TASK-260728-3bj9bk: pin-sparkle-public-key-and-verify-appcast-signing

## Description
Complete the Sparkle update-signing integration that could not exist at the key ceremony. Pin the generated EdDSA public key as SUPublicEDKey in the generated macOS app Info.plist, wire the private key into the release pipeline as a protected CI secret, and prove end to end that a signed appcast entry verifies and that a missing or wrong key fails closed. The keypair itself is produced by TASK-260717-ziprhs; this task consumes its recorded public key and does not regenerate or handle private key material locally.

## Scope
In scope: SUPublicEDKey insertion into the generated macOS host Info.plist and its Tuist manifest source of truth; binding the CI appcast signing secret to the protected release environment; a dry-run that signs a test appcast entry and verifies it with the updater vendor verification tool; negative cases for absent, malformed, and mismatched public keys, each of which must fail closed; recording the public key and its fingerprint as non-secret evidence. Out of scope: generating the keypair or touching private key bytes (TASK-260717-ziprhs); Developer ID signing and notarization (TASK-260715-3sk5cd, TASK-260715-387eof); publishing real release assets (TASK-260715-1njthi); updater UI and scheduling (TASK-260717-rk4mi7); iOS.

## Acceptance Criteria
1. SUPublicEDKey in the generated macOS app matches the public key recorded by TASK-260717-ziprhs exactly, and the value is produced by the project manifest rather than a hand-edited generated artifact. 2. A pipeline dry-run signs a test appcast entry with the CI secret and the updater vendor verification tool accepts it against the pinned public key. 3. Absent, malformed, and mismatched signing keys each fail the pipeline closed with a distinguishable error, and no unsigned or unverified appcast entry can be published. 4. The private key is present only as a protected-environment CI secret; it is absent from git, board resources, artifacts, caches, and logs, and forks and pull requests cannot reach it. 5. A TASK-ID-scoped outcome records the public key, its fingerprint, the verification tool version, the dry-run transcript with secrets masked, and the negative-case results.
