# Establish evidence-gated DNS profile and runtime limits

## Description
Produce the accountable evidence decision for every numeric DNS value deliberately deferred by ADR-022 so production profile validation and DNS transports receive one versioned injected policy rather than unevidenced constants.

## Scope
In scope: maximum configured endpoint count; DNS TCP message and framing bytes; per-query reservation and aggregate DNS memory accounting; in-flight and queued-byte capacities; SSH channel-open, response, logical-query, startup-readiness, and idle-close timing; structural M1 endpoint-attempt and M2 UDP-to-TCP accounting; controlled IPv4, IPv6, loopback, and unreachable resolver fixtures; extension memory and startup budgets; validation relationships; defaults, hard caps, revalidation triggers, and downstream handoff updates. Out of scope: choosing a resolver vendor, changing explicit numeric dns53 identity, implementing the DNS listener, upstream, cache, relay, or profile UI, physical-resolver fallback, DoH, discovery, and production code beyond a disposable measurement harness.

## Acceptance Criteria
1. A TASK-ID-scoped evidence report compares candidate endpoint cardinalities, message sizes, capacities, byte budgets, and timing values against primary DNS and SSH requirements, accepted runtime memory and startup contracts, and repeatable controlled-fixture measurements. 2. The selected DNSRuntimePolicyV1 names exact injectable production defaults and validation ceilings for endpoint count, maximum DNS message bytes, in-flight queries, queued and aggregate bytes, channel-open, response, logical, startup, and idle timing, and proves every cross-field relationship; no value is stored in the user profile unless ADR-022 requires it. 3. Worst-case accounting reserves request, maximum response, framing, correlation metadata, connection buffers, retry batch, and queued bytes within an explicit DNS component budget; inconsistent policies fail validation and measurements record peak footprint and cleanup. 4. Reliability evidence covers IPv4-only, IPv6-only, dual ordered, loopback, unreachable, malformed, and stalling endpoints, concurrent connection failure, cancellation, and M2 one-UDP-plus-bounded-TCP semantics with no physical resolver access. 5. An independent architecture reviewer accepts the values and revalidation triggers, and the task updates ADR-022, the routing and DNS source of truth, test vectors, and concrete downstream task resources before production composition or profile UX consumes defaults.
