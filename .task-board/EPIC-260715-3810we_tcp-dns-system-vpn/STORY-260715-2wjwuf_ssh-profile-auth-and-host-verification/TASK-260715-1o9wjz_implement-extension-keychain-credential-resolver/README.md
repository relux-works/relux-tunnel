# Implement the macOS provider system-domain Keychain credential resolver

## Description
Implement least-privilege read-only retrieval of the selected private key and optional passphrase from the macOS file-based system-domain Keychain using only the exact opaque credential reference from the validated profile. Resolve the keychain with SecKeychainCopyDomainDefault(kSecPreferencesDomainSystem), scope SecItemCopyMatching through an explicit kSecMatchSearchList, bound secret lifetime, prevent logging or serialization, and return stable privacy-safe access and format errors.

## Scope
In scope: Security-framework query abstraction; system-domain keychain resolution without a hard-coded path; fixed non-identifying service plus exact credentialRef match; kSecUseDataProtectionKeychain=false; explicit kSecMatchSearchList; item identity/type validation; imported and generated key representations supported by libssh2; optional passphrase retrieval; read-only startTunnel behavior; cancellation; scoped secret container; best-effort mutable-buffer clearing; unit and provider-context tests. Out of scope: key import or generation; Keychain UI; password authentication; biometric prompts; credential sync; exporting keys; ambient search-list queries; kSecAttrAccessGroup or kSecAttrAccessible; engine selection; physical root-provider provisioning validation.

## Acceptance Criteria
1. Queries resolve the system-domain keychain through SecKeychainCopyDomainDefault and use only an explicit kSecMatchSearchList, fixed service constant, and exact opaque credential reference; no ambient search list, enumeration, fallback, hard-coded keychain path, access group, or accessibility attribute exists. 2. credentialNotProvisioned, inaccessible, wrong-class, malformed, passphrase-required, unsupported-key, and cancellation outcomes are distinct and privacy-safe before authentication. 3. Secret values never enter providerConfiguration, logs, metrics, crash annotations, Codable/public models, test snapshots, board resources, or shell output. 4. Secret containers have bounded lexical or asynchronous lifetime and best-effort clearing where APIs permit, with limitations documented; startTunnel is read-only and never seeds or waits for credentials. 5. Swift Testing and provider-context seams prove exact-match success, unrelated item/search-list denial, query-shape correctness, cancellation release, format handling, and redaction; non-secret evidence is attached.
