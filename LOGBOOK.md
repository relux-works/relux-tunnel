### 0623 — Unstructured Tasks give exactly-once but not first-wins (BUG-260728-3jfjkh)
- ROOT CAUSE: `TunnelProviderAdapter.providerDidFail` was `nonisolated` and deferred *all* admission into a freshly spawned unstructured `Task`. Swift orders nothing between unstructured tasks contending for the same actor, so two sequential provider-failure callbacks could enter `handleProviderFailure` in reverse order. The `cancelTunnelIssuedGeneration` ledger enforced exactly-once but had no notion of *which* call arrived first, so the second error (`internalInvariant` 1009) beat the first (`runtimeStartupFailed` 1007) in **10 of 40** focused runs (~25%).
- FINDING: A generation ledger consulted *inside* the actor cannot recover call order that was already lost at the task-spawn boundary. Ordering has to be captured where the caller still exists — on the caller's thread — not where the work is executed.
- FIX: Added file-private `ProviderFailureAdmission` (`NSLock`-guarded claim flag) in `Sources/ReluxTunnelCore/ProviderLifecycle.swift:461`. `providerDidFail` now claims admission **synchronously** before spawning the task (`ProviderLifecycle.swift:907`); later and concurrent callers are dropped before reaching the actor. `startGeneration` releases the claim when it bumps `latestGeneration` (`ProviderLifecycle.swift:632`), keeping admission generation-scoped exactly as the old ledger was.
- DECISION: Removed `cancelTunnelIssuedGeneration` rather than keeping it as a second guard. With synchronous admission it is unreachable-by-construction, and two independent exactly-once authorities on the same callback invite divergence later. `handleProviderFailure` now calls `cancelTunnelWithError` unconditionally.
- SCOPE: `Sources/ReluxTunnelCore/ProviderLifecycle.swift` (+26/−6) and `Tests/ReluxTunnelCoreTests/ProviderAdapterContractTests.swift`. Both platform seams inherit the fix — `IOSProviderCompositionRoot.swift:146` and `MacOSProviderCompositionRoot.swift:146` forward straight to the shared adapter. NSError codes, stop/join semantics, and cleanup-registry behavior unchanged.
- VERIFICATION: New `providerFailureFirstCallOrdering` (50 double-failure cycles × 2 seams) fails on both seams with the source fix stashed and passes with it — a real regression guard, not a tautology. `providerFailureConcurrentAdmission` (16 concurrent calls, each cancel handler reentrantly re-calling `providerDidFail`) pins exactly-once and no-deadlock, which is what protects the `cancelTunnelIssuedGeneration` removal. Focused `providerFailureHandoff`: **0/30 failures**. `make validate-core` exit 0, 335 tests / 29 suites. `swift-format lint --strict` exit 0.
- STATUS: Ready for review; not yet independently reviewed (AC5).
