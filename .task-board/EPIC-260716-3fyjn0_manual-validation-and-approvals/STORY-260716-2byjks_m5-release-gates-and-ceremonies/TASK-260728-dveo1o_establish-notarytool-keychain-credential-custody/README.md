# TASK-260728-dveo1o: establish-notarytool-keychain-credential-custody

## Description
Prove and record the Keychain-only notarization custody required by ADR-025 before any notarization step is declared ready. The interactive notarytool store-credentials run and the owner disposition decision for the source App Store Connect API private-key file happen once inside Ceremony C1 (TASK-260728-q5kjta). This task runs unattended afterwards: it verifies that the NAMED Keychain profile authenticates against the real Apple notary service using only its name, records the non-secret evidence and the disposition the owner chose, defines rotation and revocation, and scans for leaks. The agent never receives, echoes, or persists secret values.

## Scope
In scope: a read-only notary history or whoami style authentication check performed with the named login-Keychain profile alone; recording the profile name, the fact a profile exists, the authenticating team identifier, and the check outcome; transcribing the owner-approved disposition chosen at C1 for the source .p8 file from Keychain-backed migration, retention under a named custodian with documented access control, or secure destruction, and verifying that the stated disposition actually holds; a repeatable rotation and revocation procedure keyed to the profile name; shell-history and command-echo suppression plus a post-run leak scan. Out of scope: performing the interactive store-credentials or making the disposition decision (TASK-260728-q5kjta owns both); recording or transmitting the source file path, key ID, issuer ID, passphrase, or key bytes anywhere; submitting a real notarization of a product artifact; configuring CI notarization secrets (TASK-260715-3gkwn0 owns the separately-scoped CI credential); Developer ID certificate issuance; iOS or App Store Connect distribution credentials.

## Acceptance Criteria
1. A read-only authentication check succeeds using only the named notarytool Keychain profile, with the command transcript showing no secret value. 2. A TASK-ID-scoped outcome records the profile name, the authenticating team identifier, the check outcome, the date, and the rotation/revocation procedure; it records no file path, key ID, issuer ID, passphrase, or key bytes. 3. The owner-approved disposition of the source App Store Connect API private-key file chosen at Ceremony C1 is transcribed and independently verified to hold; a mode-0600 file left in place with no recorded custodian is an explicit fail. 4. Shell history and command echo are suppressed for every command, and a post-run scan of the repository, board resources, shell history, and run logs finds no notarization secret material. 5. If the profile is absent, fails to authenticate, or the disposition was not decided at C1, the task records the exact blocking input needed and remains blocked rather than reporting a ready notarization path.
