# Implement VPN session control and truthful status projection

## Description
Implement the host controller from TASK-260715-1q4qhw. Start and stop only the freshly reloaded owned NETunnelProviderSession, observe system status as authority, request fresh read-only provider snapshots for capability authority, and reconcile after app relaunch without owning forwarding.

## Scope
In scope: current-status preflight; bounded v1 start request matching stored configuration; synchronous start errors; 60-second connect observation; cancel-start stop; 15-second disconnect observation; initial status read plus exact-session notifications; 3-second read-only message and last-disconnect-error requests; exact public connection-error/provider-error/nil-error mapping; protocol negotiation; generation/sequence freshness; controller retirement and host relaunch. Out of scope: final UI wording, automatic reconnect, mutating provider RPC, profile switching UX, UDP implementation, analytics, manager persistence, and app-owned runtime state.

## Acceptance Criteria
1. Start requires a fresh exact-owned current enabled manager and maps every NEVPNStatus preflight/terminal row and last-disconnect result without duplicate system calls; cancellation/60-second timeout stops and never claims connected. 2. Stop is idempotent, joins connecting/connected/reasserting/disconnecting work, observes terminal status for 15 seconds, and never claims cleanup on timeout. 3. Projection preserves NETunnelProviderSession as system-state authority and current provider snapshots as capability authority; every non-connected status clears capability and missing/stale/unsupported/out-of-order facts never synthesize it. 4. Read-only v1 messages enforce 3-second timeout, request correlation, size/version/schema/generation ordering, and controller-generation retirement. 5. Tests cover every status, all public NEVPNConnectionError values, provider/unknown/nil errors, fetch timeout/cancellation, app recreation, observer/task release, start/stop races, nil/late provider responses, and fresh recovery from system plus provider state.
