# Implement the owned NETunnelProviderManager repository

## Description
Implement the shared host-side repository from TASK-260715-1q4qhw. Load only app-scoped NetworkExtension preferences, apply the exact protocol/provider-ID/owner-marker predicate, create or replace one canonical non-secret configuration, separate ensure from explicit enable, reload after every write, and expose explicit duplicate repair and owned-only removal.

## Scope
In scope: 15-second operation tokens; nil-collection fail-closed load; exact owned predicate; canonical protocol fields and 4 KiB configuration-reference Data; zero/one idempotent ensure; duplicate and unmarked-lookalike conflicts; current-schema inactive duplicate repair; future-schema preservation; explicit enable/disable/remove; save/reload verification; one stale retry; late callback retirement; authorization and stable error mapping; mixed-manager tests on iOS/macOS seams. Out of scope: secrets, profile selection UX, connect/status control, automatic enable, editing or removing unrelated/future-owned managers, account migration, final labels/uninstall UX, and provider runtime.

## Acceptance Criteria
1. Zero/one-owned repeated ensure converges to one canonical disabled-or-preserved-state configuration; enable is a separate explicit user-intent save/reload operation, while a nil managers collection is a zero-write failure. 2. The exact ownership truth table records zero setter/save/remove calls for unrelated, lookalike, wrong-type, unmarked, and unsupported-future managers; duplicate repair/removal touches only freshly revalidated supported exact-owned inactive managers. 3. providerConfiguration contains exactly the stable marker, manager contract version, and bounded encoded opaque profile reference, with secret/type-confusion tests. 4. Save/reload, one stale retry, timeout/cancellation late callbacks, authorization failure, corruption, future schema, duplicate-active conflict, and saved-but-reload-failed return the contract errors without stale-object reuse. 5. iOS/macOS host seams compile against injected PlatformVPNIdentity, production identity fails closed until TASK-260715-ypo7yo and applicable release bindings are accepted, and tests cover the system effect of explicit enterprise-VPN enablement.
