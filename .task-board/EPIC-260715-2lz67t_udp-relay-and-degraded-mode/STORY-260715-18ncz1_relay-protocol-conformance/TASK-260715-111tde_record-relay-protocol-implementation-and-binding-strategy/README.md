# Record the relay protocol implementation and binding strategy

## Description
Freeze the relay protocol v1 implementation and binding strategy on the accepted ReluxTunnelCore ownership, Go relay toolchain, and candidate-neutral SSH exec-channel contracts before wire implementation begins.

## Scope
In scope: consume TASK-260715-2nfz7w, TASK-260715-3bdplx, TASK-260720-100wu6, ADR-005/006, relay/security specs, and the accepted override; canonical language-neutral schema; Swift and Go bindings; generated versus handwritten ownership; deterministic regeneration and CI drift; module placement; endian and bounded-stream primitives; identity preflight; handshake, framing, association, close/error, DNS priority and backpressure contracts; dependency/license/trust ceilings; shared vectors; versioning/review rules; downstream consumer mapping. Numeric association, queue, datagram, idle, and hard ceilings remain owned by TASK-260715-18owh7. Out of scope: reselecting language/project generator/SSH engine, implementing codecs or sockets, building assets, remote bootstrap implementation, Gate A0, generated Apple workspace ownership, and protocol v2 design.

## Acceptance Criteria
1. A TASK-ID-scoped decision record references the approved project and relay-toolchain ADR and names the exact schema, generated outputs, handwritten adapters, modules, and owners. 2. It defines one deterministic regeneration command, reviewable generated diffs, and a CI drift check that fails hand-edited or stale outputs. 3. The chosen byte and stream abstractions operate within the Apple extension and rootless Linux or macOS constraints without blocking I/O or unbounded allocation. 4. Runtime dependencies, licenses, unsafe or FFI use, error surfaces, and source-versus-build trust boundaries are enumerated and remain within the approved ceiling. 5. Every downstream protocol, build, bootstrap, and UDP task maps to a concrete artifact or interface in the decision and has no unresolved language choice.
