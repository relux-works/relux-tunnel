# Add integrated tunneled DNS, external-IP, and no-leak harness tests

## Description
Exercise the composed M1 runtime in controlled harness and macOS development contexts with dual-stack TCP traffic, client UDP and TCP DNS, SSH DNS-over-TCP, route settings instrumentation, external-IP endpoints, forced resolver or SSH failures, and physical-path DNS monitors. Prove correctness before the physical-device matrices.

## Scope
In scope: controlled IPv4 and IPv6 web or echo destinations, external address observation, authoritative DNS fixtures, client UDP and TCP DNS, SSH DNS-over-TCP, route settings instrumentation, external-IP endpoints, ordered resolver endpoints, shared-connection concurrent failure and coordinated promotion, cache generation, forced resolver or SSH failures, physical-path DNS monitors, injected DNSRuntimePolicyV1 boundary vectors, repeated start and stop, diagnostics reconciliation, and privacy-safe captures. Out of scope: general UDP forwarding, public resolver benchmarking, path transitions, captive recovery, fail-closed mode, QUIC, final physical iPhone evidence, and production traffic.

## Acceptance Criteria
1. Representative TCP and DNS fixture traffic succeeds through one authenticated SSH host for IPv4 and IPv6, and observed external addresses and resolver source match the configured exit fixtures. 2. Client UDP and TCP DNS traverse the M1 SSH DNS-over-TCP transport, cache and truncation cases behave correctly, and the physical resolver sentinel observes zero ordinary post-settings queries. 3. A reusable connection failure with multiple in-flight queries produces one atomic retired epoch, one coordinated promotion, ordered retry of eligible queries, terminal treatment of cancelled and expired queries, no per-query reopen storm, no duplicate visible answer from late old-epoch callbacks, and cache-generation invalidation. 4. Valid NXDOMAIN, SERVFAIL, and REFUSED responses never cause resolver shopping; channel-open failure, partial write, timeout, malformed or mismatched response, SSH loss, settings failure, DNS component failure, and endpoint exhaustion produce bounded explicit outcomes, mandatory teardown when required, and zero physical fallback. 5. Injected policy boundary runs cover message, in-flight, queued, aggregate-byte, and deadline admission; repeated runs reconcile runtime, packet, TCP, DNS, connection-epoch, promotion, route, and drop counters and return tasks, buffers, channels, and cache state to baseline.
